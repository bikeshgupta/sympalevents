WHAT IT DOES (plain words)
  Makes the app's existing visit tracking able to describe more than event pages, without a second set of
  tables. event_visits and event_page_views keep their names and keep working exactly as before; they gain
  a "surface" (which part of Sympal), an optional society, and an optional event. It also adds
  app_users.last_seen_at, seeded once. Nothing is renamed, dropped or deleted, and no application code
  changes with this migration: the new columns simply wait for the code that fills them.

WHAT IT CHANGES
  event_visits and event_page_views, each:
    + surface text not null default 'event'        every existing row becomes 'event' (they all are)
    + organization_id uuid null  -> organizations, ON DELETE SET NULL    (existing rows filled from their event)
    ~ event_id: NOT NULL removed; its foreign key changes from ON DELETE CASCADE to ON DELETE SET NULL
    + 2 indexes (by society, by surface) alongside the existing per-event index
    + a tidy-shape CHECK on surface; table and column comments
  app_users:
    + last_seen_at timestamptz null, seeded once from updated_at where null (below)
    + comments on last_seen_at and updated_at

HOW A VISIT IS SCOPED (stored here, applied by code later)
  scope = surface + organization_id + event_id. One visit = one continuous stay in one scope, in one tab.
    society / TRU / -            Society Home visit
    society_admin / TRU / -      a NEW visit
    event / TRU / Ganesh         a NEW visit; Overview -> Schedule -> Gallery stay ONE visit (page views)
    event / TRU / Badminton      a NEW visit
    profile / - / -              its own visit
    event_create / TRU / -       its own visit
    proposal / TRU / -           its own visit
  Surfaces: event, society, society_admin, profile, event_create, proposal. Login is not tracked. The
  list is enforced by the SERVER, not by a database constraint, so adding a surface is a reviewed code
  change; the CHECK only keeps the column lower-case letters and underscores.

ABOUT THE ONE-TIME SEED (app_users.last_seen_at = updated_at where last_seen_at is null)
  Until now the server rewrote updated_at on every authenticated request, so it is the best record there is
  of when each person was last active. The seed copies it once so the field is not empty on day one.
  - The seeded values are APPROXIMATE HISTORICAL AUTHENTICATED ACTIVITY inferred from that legacy
    behaviour. A profile edit also moves updated_at. They are not recorded activity.
  - Do NOT use them to claim historical daily/weekly active users, or to reconstruct activity that was never
    recorded. Real activity starts being recorded when the tracking code ships.
  - After 045 and that code, last_seen_at is the authoritative activity field. updated_at returns to meaning
    "the user record was modified", but only once the separate requireAppUser change ships (see section 6);
    until then it is still rewritten per request and its column comment says so.
  - The seed runs only when the column is being created, so re-running the file can never re-seed.
  - Anonymous activity never affects last_seen_at (a code rule; there is no database mechanism for it).

DELETION AND RETENTION (confirmed)
  event_id and organization_id are ON DELETE SET NULL: traffic facts survive the deletion of an event or a
  society and stop being attributable to it (a society delete cascades to its events, so both become null).
  No cascade deletes traffic history anywhere. No retention or pruning is added; nothing deletes raw rows.
  Behavioural events are not created or collected.

PREREQUISITES: 045 needs migration 028 (event_visits) AND migration 030 (audit_log + event_page_views) to be

-- V7. Behaviour test. Creates a throwaway society, event, visits and users and proves: code written before
--     045 (no surface, no society) still inserts and gets surface 'event'; society/profile visits need no
--     event; a malformed surface is refused; deleting an event keeps its traffic and its society attribution;
--     deleting a society keeps the traffic with no society; deleting a user keeps their visits; the
--     conditional once-an-hour last_seen_at statement writes once and then not again inside the hour; then it
--     deletes everything it made. Expect a NOTICE starting with OK. (Run on a scratch PostgreSQL built from
--     migrations 001-046, with pre-existing traffic loaded first, and passed; also re-run-safe.)
do $$
declare
  org uuid; ev uuid; u uuid; v1 uuid := gen_random_uuid(); v2 uuid := gen_random_uuid(); v3 uuid := gen_random_uuid();
  n int; failed boolean; before_seen timestamptz;
begin
  insert into public.app_users (firebase_uid, email, full_name) values ('__a_u','__a_u@test.invalid','A U') returning id into u;
  insert into public.organizations (name) values ('__activity_test__') returning id into org;
  insert into public.events (organization_id, name, start_date, end_date) values (org, 'AEv', current_date, current_date) returning id into ev;

  -- 1. code written before 045 still works: no surface, no organization given -> 'event', null org
  insert into public.event_visits (id, event_id, visitor_key, page_key) values (v1, ev, '__vk', 'dashboard');
  if (select surface from public.event_visits where id = v1) <> 'event' then raise exception 'FAILED 1: default surface'; end if;
  -- 1b. such rows get their society from the idempotent post-deploy backfill
  update public.event_visits v set organization_id = e.organization_id from public.events e where e.id = v.event_id and v.organization_id is null;
  if (select organization_id from public.event_visits where id = v1) is distinct from org then raise exception 'FAILED 1b: backfill'; end if;
  -- 2. a non-event surface needs no event
  insert into public.event_visits (id, visitor_key, surface, organization_id, page_key) values (v2, '__vk', 'society', org, 'home');
  insert into public.event_page_views (visit_id, surface, organization_id, page_key) values (v2, 'society', org, 'home');
  insert into public.event_visits (id, visitor_key, surface, page_key) values (v3, '__vk', 'profile', 'profile');
  -- 3. a malformed surface is refused
  failed := false; begin insert into public.event_visits (id, visitor_key, surface) values (gen_random_uuid(), '__vk', 'Bad Surface!'); exception when check_violation then failed := true; end;
  if not failed then raise exception 'FAILED 3: bad surface accepted'; end if;
  insert into public.event_page_views (visit_id, event_id, organization_id, page_key) values (v1, ev, org, 'dashboard');
  -- 4. deleting the EVENT keeps its traffic; the society attribution stays
  delete from public.events where id = ev;
  if (select count(*) from public.event_visits where id = v1 and event_id is null) <> 1 then raise exception 'FAILED 4a: event visit lost or still pointing'; end if;
  if (select organization_id from public.event_visits where id = v1) is distinct from org then raise exception 'FAILED 4b: society attribution lost on event delete'; end if;
  if (select count(*) from public.event_page_views where visit_id = v1 and event_id is null and organization_id = org) <> 1 then raise exception 'FAILED 4c: page view'; end if;
  -- 5. deleting the SOCIETY keeps the traffic, unattributed
  delete from public.organizations where id = org;
  select count(*) into n from public.event_visits where id in (v1, v2) and organization_id is null;
  if n <> 2 then raise exception 'FAILED 5a: visits lost or still attributed (%)', n; end if;
  if (select count(*) from public.event_page_views where visit_id in (v1, v2) and organization_id is null) <> 2 then raise exception 'FAILED 5b: page views'; end if;
  -- 6. deleting the USER keeps their visits (already so)
  update public.event_visits set user_id = u where id = v3;
  delete from public.app_users where id = u;
  if (select count(*) from public.event_visits where id = v3 and user_id is null) <> 1 then raise exception 'FAILED 6'; end if;
  -- 7. last_seen_at: new users start null; the conditional once-an-hour update behaves
  insert into public.app_users (firebase_uid, email, full_name) values ('__a_u2','__a_u2@test.invalid','A U2') returning id into u;
  if (select last_seen_at from public.app_users where id = u) is not null then raise exception 'FAILED 7a: new user has a last_seen_at'; end if;
  update public.app_users set last_seen_at = now() where id = u and (last_seen_at is null or last_seen_at < now() - interval '1 hour');
  select last_seen_at into before_seen from public.app_users where id = u;
  if before_seen is null then raise exception 'FAILED 7b: first write did not happen'; end if;
  update public.app_users set last_seen_at = now() + interval '1 second' where id = u and (last_seen_at is null or last_seen_at < now() - interval '1 hour');
  if (select last_seen_at from public.app_users where id = u) <> before_seen then raise exception 'FAILED 7c: a second write inside the hour went through'; end if;
  update public.app_users set last_seen_at = now() - interval '2 hours' where id = u;
  update public.app_users set last_seen_at = now() where id = u and (last_seen_at is null or last_seen_at < now() - interval '1 hour');
  if (select last_seen_at from public.app_users where id = u) < now() - interval '1 minute' then raise exception 'FAILED 7d: a stale value was not refreshed'; end if;

  delete from public.event_page_views where visit_id in (v1, v2, v3);
  delete from public.event_visits where id in (v1, v2, v3);
  delete from public.app_users where id = u;
  raise notice 'OK: old-style inserts default to event; non-event surfaces work; event and society deletion keep traffic (set null); last_seen_at throttle is conditional; test data removed';
end $$;

-- V8. Nothing left behind (expect 0, 0, 0).

       (select count(*) from public.app_users where email like '\_\_a\_%@test.invalid') as users,

5. ROLLBACK CONSIDERATIONS
------------------------------------------------------------------------------------
- The migration is additive/loosening, so the app does not need rolling back with it: old code ignores the
  new columns and works against either shape.
- Rolling back LOSES information. The old shape cannot hold a visit with no event, so rows that have no
  event (every non-event surface, and event traffic whose event was deleted after 045) cannot be kept in the
  original tables. The block below first copies them into two archive tables, then removes them from the
  originals. The archive tables hold visitor keys: drop them when you no longer need them.
  Dropping surface/organization_id and last_seen_at also discards those values (the seeded last_seen_at
  cannot be re-created exactly afterwards).
- Rolling back restores ON DELETE CASCADE on event_id, i.e. deleting an event deletes its traffic again.
- Tested on the scratch database: archive, rollback, and re-applying 045 afterwards all worked.

-- 0. Keep the rows the old shape cannot hold (non-event surfaces, and traffic of events deleted since 045).
create table public.event_visits_045_archive     as select * from public.event_visits     where event_id is null;
create table public.event_page_views_045_archive as select * from public.event_page_views where event_id is null;

begin;
delete from public.event_page_views where event_id is null;
delete from public.event_visits     where event_id is null;

alter table public.event_visits drop constraint if exists event_visits_event_id_fkey;
alter table public.event_visits add constraint event_visits_event_id_fkey
  foreign key (event_id) references public.events(id) on delete cascade;
alter table public.event_visits alter column event_id set not null;
drop index if exists public.event_visits_org_started_idx;
drop index if exists public.event_visits_surface_started_idx;
alter table public.event_visits drop constraint if exists event_visits_surface_shape;
alter table public.event_visits drop column if exists surface, drop column if exists organization_id;

alter table public.event_page_views drop constraint if exists event_page_views_event_id_fkey;

alter table public.event_page_views alter column event_id set not null;
drop index if exists public.event_page_views_org_opened_idx;
drop index if exists public.event_page_views_surface_opened_idx;
alter table public.event_page_views drop constraint if exists event_page_views_surface_shape;
alter table public.event_page_views drop column if exists surface, drop column if exists organization_id;

comment on table public.event_page_views is null;
