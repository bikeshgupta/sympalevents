MIGRATION 047 - platform_access_log  (prepared for review; YOU run it by hand)
File: supabase/migrations/047_platform_access_log.sql
Status: PREPARED, NOT APPLIED. Nothing in the app needs it: until it is applied, the Control Center's
"Attempts to open this area" list says it is not recorded yet, and the refusals stay in the Vercel function log.

WHAT IT DOES (plain words)
  Records each time a SIGNED-IN person opens, or is refused at, the owner-only Platform Control Center
  (/platform/analytics), so the owner can see it inside the product. The owner opening the area is recorded as
  allowed; a signed-in person who is not the owner is recorded as refused. At most one row per person per
  outcome per five minutes, so refreshing cannot fill the table.

WHAT IT ADDS (and only this)
  - table public.platform_access_log  (row level security ON, no policies)
  - 2 indexes
  It changes no existing table, column or row.

WHAT IS KEPT, AND WHAT IS NOT
  Kept: when, allowed or refused, a short reason word, which part was asked for, and the account id.
  Not kept, in any form: IP address, browser/user agent, token, email. The account's name is looked up when the
  page is read. A request with no token, or a token that does not verify, writes NOTHING - so a stranger
  hammering the address cannot fill the table. Those requests are in the Vercel function log only.
